# Help Center (in-app user manual) — Part 1 design

Date: 2026-11-08 · Status: approved in brainstorming, awaiting spec review

## Goal

A user manual inside the app that a person with little computer experience can
follow: short task articles, numbered steps, real screenshots with the exact
button ringed and magnified, a worked example in every article. Offline (desktop
app), same theme as the app, Arabic first.

## Decisions (owner, 2026-11-08)

| Topic | Decision |
|---|---|
| Where | Inside the app, offline. No external site, no CDN. |
| Language | Arabic first. French/English later by translating finished articles. |
| Pilot scope | Getting started + Players. |
| Article style | Step cards + magnifier bubble + one worked example per article. |
| Entry points | Help Center page + a `?` button on every page (side panel). No guided tours in Part 1. |
| Screenshots | Automatic Playwright script on a demo club; regenerated by one command. |
| Visibility | Users only see articles for modules they can view. |
| Storage | Markdown files in the repo, parsed by Laravel, rendered by Vue. |
| Author | Claude drafts the Arabic text from the code; owner reviews. |
| Theme | Always the app's own theme: same components, the club's chosen primary colour (Settings branding preset/custom), fonts, light/dark; screenshots shown in the user's current mode. |
| Screenshot colour | Captured once in the default emerald preset, light + dark. A club on another colour sees emerald inside the pictures; everything around them follows the club colour. Markers stay amber (they sit on emerald shots). |

## 1. Content

### Files

```
resources/help/
  README.md                      how to write an article (for future authors)
  topics.php                     topic order, icon, module gate, "Start here" list
  shots.js                       screenshot shot list (used by the script)
  ar/
    getting-started/login.md
    getting-started/find-your-way.md
    getting-started/profile-password.md
    players/add-player.md
    players/find-player.md
    players/player-page.md
    players/edit-player.md
    players/documents.md
    players/branch-registrations.md
public/help-shots/ar/{light,dark}/<shot>.webp
public/help-shots/ar/<shot>.json   element boxes per data-help name
```

Topic titles are UI strings → normal i18n keys (`help.topics.players`), so the
Help Center chrome is translated in AR/FR/EN; only article bodies are Arabic-only.

### Article format

Front matter: a small flat `key: value` block (lists as `[a, b]`). Parsed by our
own tiny parser — no new Composer dependency (symfony/yaml is not installed).

```md
---
title: كيف أضيف لاعباً جديداً
summary: سجّل لاعباً جديداً في النادي في أقل من دقيقتين.
module: players
pages: [players.index, players.create]
keywords: [تسجيل, لاعب جديد, منخرط]
related: [players/find-player, players/documents]
---

مقدمة قصيرة بالنص العادي.

:::example
اللاعب **أحمد بن علي**، مولود 2012، صنف **أقل من 14 سنة**.
:::

:::step اضغط على زر «إضافة لاعب»
ستجده أعلى الصفحة، لونه أخضر.
::figure players-index ring=add-player zoom=add-player
:::

:::tip
يمكنك أيضاً الضغط على Ctrl + K والكتابة «لاعب».
:::

:::warning
تأكد من تاريخ الميلاد، فهو يحدد صنف اللاعب.
:::
```

- `module` — gate; the user needs the module's view right (same rule as the
  sidebar). Omitted for `getting-started` → every signed-in user.
- `pages` — route names whose `?` panel lists this article.
- Blocks: `:::step <heading>`, `:::tip`, `:::warning`, `:::example`, plain
  Markdown paragraphs/lists between blocks. `::figure <shot> [ring=a,b] [zoom=a]`
  inside a step (or standalone). Steps are numbered automatically.
- Inline Markdown (bold, lists, «») rendered via league/commonmark (already a
  Laravel dependency) with HTML input stripped.

## 2. Server (Laravel)

- `App\Services\Help\HelpLibrary` — loads `resources/help/{locale}/**/*.md`,
  falls back to `ar` when the locale has no articles; parses each file into
  `{slug, topic, title, summary, module, pages, keywords, related, minutes,
  blocks[]}`; blocks are typed (`text`, `step`, `figure`, `tip`, `warning`,
  `example`) with rendered HTML for text. Cached (file cache, key includes file
  mtimes) so desktop startup cost stays nil.
- `visibleFor(User)` filters by module view right; superadmin sees all.
- Routes (auth, no `permission` middleware — help is for everyone; filtering is
  per article):
  - `GET /help` → `Help/Index` (topics, start-here, articles summary list)
  - `GET /help/{topic}/{slug}` → `Help/Show`; 404 when missing or not visible
  - `GET /help/panel?route=<routeName>` → JSON list for the `?` panel (query
    string, so it can't collide with `{topic}/{slug}`)
- Search index: titles, keywords, step headings of visible articles, shared to
  the Ctrl+K palette (lazy: fetched when the palette first opens, not on every
  page load).
- Login page: link "تحتاج مساعدة في الدخول؟" → `GET /help/login` (guest route)
  rendering only the `getting-started/login` article.

## 3. Screenshots
Shots live in `public/help-shots/`. Not under public/help: a real folder there would shadow the /help route (artisan serve and Apache's !-d rewrite).

- `Database\Seeders\HelpDemoSeeder` — demo club "نادي المثال", 2 branches,
  ~22 players with realistic Arabic names, categories, document types, and the
  worked-example player أحمد بن علي. Subscriptions/payments are added when
  their articles are written (later part). Runs on a dedicated
  temporary SQLite file; never touches dev or production data.
- Vue screens get `data-help="<name>"` attributes on elements articles point at.
  No behaviour change.
- `npm run help:shots` (Playwright, devDependency only, never shipped):
  1. migrate + seed the demo DB, start `php artisan serve --no-reload` on it
     (DB env not overridable with config cache — use `APP_CONFIG_CACHE`, see
     db-swap gotchas);
  2. log in as demo admin;
  3. for each entry in `resources/help/shots.js` (`{ name, url, before: [actions],
     targets: [data-help names], viewport }`) capture light + dark WebP and write
     `<name>.json` with each target's box (x, y, w, h as % of the image);
  4. fail with article + target name when a `data-help` target is missing.
- Fixed viewport (1280×800), Arabic locale, default emerald theme, for consistency.
- Images converted to WebP with `sharp` (devDependency; Playwright only writes PNG/JPEG).

## 4. Client (Vue)

All built from existing app components, Tailwind tokens (`primary-*`, `dark:`),
fonts; renders inside the normal AppShell.

- `Pages/Help/Index.vue` — search box, green "🚀 ابدأ من هنا" banner (ordered
  start-here articles), topic tiles (only visible topics), "قرأته مؤخراً" from
  localStorage (try/catch, works without it).
- `Pages/Help/Show.vue` — title, summary, "⏱ دقيقتان", blocks, related articles,
  "هل كان هذا مفيداً؟ 👍 👎" (localStorage only, no tracking), print button
  (browser print, print stylesheet hides chrome).
- `Components/Help/HelpStep.vue` — number badge, heading, body, figure.
- `Components/Help/HelpFigure.vue` — picks light/dark shot from `useTheme`;
  draws amber ring(s) + numbered marker and a magnifier bubble (CSS
  background-position zoom of the same image) from the JSON boxes; RTL-aware;
  tap → full-screen view; missing image → grey placeholder with step text.
- `Components/Help/HelpCallout.vue` — tip / warning / example.
- `Components/Help/HelpDrawer.vue` + `?` button in AppShell top bar — side panel
  listing articles for `route().current()`; empty → "افتح مركز المساعدة" + search.
- Ctrl+K: a "المساعدة" result group.
- Amber (`amber-500`, ring offset) markers in both themes; dark mode follows the
  existing rule (primary-300 on dark, not 400).
- ≤ 640 px: cards stack, magnifier shrinks, no horizontal scroll at 320 px.

## 5. Errors and edge cases

- Missing screenshot → placeholder, page still renders.
- Malformed article → `help:check` / PHP test fails before release; at runtime
  the article is skipped and logged, never a 500.
- Article for a module the user can't view → absent from lists; direct URL 404.
- Unknown locale → Arabic articles + small "متوفر بالعربية فقط حالياً" note.
- Offline desktop → everything local.

## 6. Testing

- Pest: front-matter + block parser (each block type, numbering, figure args,
  HTML stripped); `visibleFor` per role; `/help`, `/help/{topic}/{slug}`,
  `/help/panel` responses + 404s; guest login article.
- `php artisan help:check` (reuses the PHP parser — one parser, not two;
  `npm run help:check` aliases it): every article parses, every figure has light+dark
  image and JSON, every ring/zoom name exists in the JSON, every `pages:` route
  name exists (from `php artisan route:list --json`), every `related` slug exists.
- `npm run i18n:check` for new UI keys (insert-only, flat dotted keys; no key
  segment named after a String method).
- Screenshot script is its own check (fails on missing targets).

## 7. Part 1 deliverables

1. Help Center home, article page, `?` panel, Ctrl+K group, login-page link.
2. Demo seeder + screenshot script + shot list.
3. Arabic articles: login; find your way (sidebar, search, `?`, dark mode);
   profile & password; add player; find player; player page tour; edit player;
   documents & copies; branch registrations.
4. `resources/help/README.md` authoring guide.

## Out of scope (later parts)

Subscriptions & payments, Attendance, Finance and the other modules (content
only); French/English articles; guided "show me" tours; PDF export of a module;
video clips.
